# 实施方案

## 一、方法

本方案面向道路养护场景下的沥青材料方案决策，采用"**确定性数值 + 大模型组织语言**"的总体方法：把推荐问题拆解为**场景解析、知识召回、性能预测、多目标排序、可解释报告**六步流水线，数值结论全部由确定性模块计算，大模型只负责组织与解释文案，从机制上杜绝数值幻觉。

1. **场景解析**：以 13 项字段描述养护场景（气候分区、PG 高低温等级、交通荷载、累计轴载、结构层位与类型、病害、预算、工期、环保与降噪要求、备注），表单由字段注册表驱动渲染；备注文本经大模型抽取为同构字段，采用"非空才覆盖"的合并语义。
2. **性能映射**：基于 94 条"材料—性能—场景"关系知识，规则化推导目标性能与权重（如高温 PG76、低温 −10℃、疲劳 100 万次、施工和易性 80 分），形成可追溯的目标画像。
3. **材料召回**：从 11,143 个知识块中混合检索，按"沥青类型 + 改性剂 + 级配 + 助剂"组合生成 5 个候选配方。
4. **性能预测**：预测 8 维决策指标（高温、低温、疲劳、水稳、全生命周期成本、碳排、寿命、施工）与 11 项企业实测指标（空隙率、VMA、VFA、稳定度、流值、TSR、残留稳定度、动稳定度、弯拉应变、抗拉强度、劲度模量），并输出置信区间与验收阈值达标判定。
5. **确定性排序**：min-max 归一化后按权重加权，叠加预算/工期/环保罚项得到 0–1 综合得分；同步输出逐维贡献分解（权重×归一化值），保证"Σ贡献−罚项=得分"。
6. **报告生成**：大模型依据确定性数据撰写报告，禁止引入新数值，引用编号由服务端过滤与编号化。

## 二、技术路线

技术路线为"**语料治理 → 索引构建 → 混合检索 → 决策计算 → 交互呈现**"五层。

- **语料层**：42 条材料知识条目（94 条关系）按维度拆分为 94 个维度级知识块；8 部规范拆出 57 条条文；142 条文献题录；40 篇论文全文经文档解析产出 9,753 个章节块；另从论文版式中结构化抽取 1,041 个含数值表格块；企业资料 56 块（胶结料 7、再生添加剂 4、料源与级配目录 45）。语料 JSON 为真相源，构建清单记录内容哈希，支持一键重建。
- **索引层**：LanceDB 为默认向量库，SQLite FTS5 为兜底引擎；每个知识块记录来源文档、内容哈希、嵌入模型、模型版本、维度、流水线修订、嵌入时间七项溯源。
- **检索层**：BM25 与向量混合检索，RRF 融合（k=60，权重可配置），按文档类型与场景标签过滤；每个候选以"场景词 + 配方全字段 + 优势维度"构造三段查询，召回 top-20 后执行一次批量 LLM 重排（5 查询×6 候选，实测 2.4–3.1s，失败回退原序）。
- **决策层**：契约层用 zod 定义全部数据结构，模块 A（映射）与 C（预测）通过适配器接口接入，当前提供确定性 mock 适配器并显式标注；排序与代价计算全部确定性实现。
- **交互层**：后端提供 REST 与 SSE 接口，报告支持流式生成（步骤事件、分段事件、完成事件）；前端采用双页式工作台（参数页 → 结果页），结果页包含指标卡、流式报告、雷达、基准对比、实测指标、分析可视化与可停靠追问侧板。

## 三、关键技术

1. **维度级切块与结构化表格证据**：将"综述式大卡"拆成维度块（如"SBS 改性沥青｜高温性能"），标签携带维度与场景，解决"库大但反复只召回几条"的问题；表格块来自论文结构化解析结果，含表题、来源与数值单元格，使证据从"结论级"升级为"定量级"。
2. **混合检索与批量重排**：中文检索以子串与词表匹配为主，向量采用多语种嵌入模型（384 维，query/passage 前缀区分），RRF 融合后由大模型批量重排；证据按"知识≤2、规范≤1、表格优先、文献/章节 1–2"配额挑选，并做全局复用上限与跨节去重。实测每案例 15 个证据槽位去重 13–15 条，任意两候选证据集合互异，全部候选均含文献、规范、章节或表格类证据。
3. **可解释与可溯源**：证据编号可点击定位并高亮；得分瀑布图逐维分解（贡献求和与综合得分误差小于 1e-6）；特征贡献图展示配方特征影响方向，并明确标注"模拟阶段确定性生成，真实预测模块接入后自动替换"。
4. **鲁棒性与降级**：大模型不可用时切换模板文案；检索不可用时切换兜底引擎或给出空库指引；重排超时回退融合原序；流式失败回退整包接口；模块未接入时以 mock 适配器兜底并打标"模拟数据"。
5. **工程实现**：pnpm 单仓库多包（契约、检索、嵌入、后端、前端、脚本）；表单与证据展示均由契约与字段注册表驱动，新增字段不改 UI；后端基于 Hono 与 zod-openapi 提供 OpenAPI 文档；前端 Vue 3 + TypeScript + Element Plus + ECharts + Pinia，报告流式消费与富文本渲染（表格、标题、列表、实体解码均有白名单净化）。

## 四、实验手段

1. **金标准召回**：38 条用例覆盖 8 个决策维度 × 4 类语料，采用与生产一致的混合检索口径（每查询取 topK×3 命中、按源文档去重后取前 5），recall@5 全部达标（38/38）。
2. **引用支撑率**：以"证据 + 完整确定性数据"为上下文，由裁判模型逐段判断报告主张是否有依据，5 个案例 49/49 段全部支撑（阈值 85%）；同时设人造幻觉自检用例，确保裁判能识别无依据数值。
3. **端到端确定性**：5 个典型案例各请求 3 次，对候选、雷达、实测指标、基准等数值字段逐字节比对一致；剔除对象仅限大模型影响面（报告文案、步骤耗时、证据顺序与重排耗时）。
4. **消融实验**：嵌入模型对比（768 维升级版金标准 37/38、重建耗时 1602s、证据更聚集，劣于现有 384 维 38/38、729s）；查询扩展对比（bigram 持平、同义词扩展召回降至 19/38）；多样性重排对比（开启后去重 8–12/15、文献参与 17/25，劣于关闭的 13–14/15、22/25）。三项均按数据结论否决，维持现配置。
5. **降级路径验证**：大模型关闭、模块不可达、空知识库三类场景的端到端测试均通过，主流程不中断、告警可见。

## 五、方案实现形态

交付形态为**开源单仓库系统**：前端 Web 应用、后端 API 服务、共享契约与检索/嵌入包、脚本工具、语料与索引数据、规格与交付文档。部署为单机 Node 服务（端口 3010）加前端开发服务（5174），通过环境变量控制模型、检索后端与各类开关，支持离线运行（模型本地缓存 + 兜底向量库）。

交互形态为"**首页叙事 → 参数页 → 结果页**"：首页呈现系统能力、数据底座与典型案例；参数页支持案例一键回填与必填校验；结果页以 KPI 卡、流式报告、八维雷达、基准对比、企业实测指标、得分瀑布与特征贡献、证据链、追问侧板组成完整决策链路。接口包括推荐（整包与流式）、对话、知识库检索/统计/上传、案例与健康检查。

## 六、质量保障与协作

测试覆盖契约、嵌入、检索、后端、前端与脚本六个包，共 300 余条单元/集成用例，另有 5 个案例的端到端回归与降级路径回归；匿名性审计脚本检查仓库元数据与文案。开发流程采用规格驱动：先写设计与计划，再按任务拆解实施，由独立评审角色按期门禁审查（严重与重要问题全部闭环），前端另经多轮视觉与交互评审并以浏览器实测验收。
