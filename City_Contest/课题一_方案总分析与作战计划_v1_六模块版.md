## 0. 先看结论（给团队的一句话）

你们目前的想法 **方向正确，但有一处关键结构性偏差需要改**：

- 你们把"场景→材料"用 LLM+RAG **一步到位**，而赛题真正要的是 **两段式量化链路**：`场景 → 目标性能指标（映射模型）→ 材料配方（反向设计/推荐引擎）`。
- 赛题反复强调的痛点是"**材料推荐缺乏量化依据**"，所以 **不能让 LLM 自由生成配方**（会幻觉、无量化依据、评委一眼看穿）。正确定位是：**LLM 负责编排/解释/报告，量化依据来自"向量知识库(RAG) + 结构化关系表 + 性能预测模型 + 优化器"**。
- 你们的第 2 步"把材料丢进模型测性能"应该 **前移进推荐循环内部**，作为优化器的"代理模型（surrogate）"来给候选配方打分，这才叫真正的"反向设计"，而不是先拍配方再补测。

改完之后的主线（推荐采用）：

```
养护场景(气候分区+交通荷载+病害特征+约束)
   └─[模块A 映射]→ 目标性能指标 + 优先级权重
        └─[模块B 推荐引擎: 向量库+结构表召回 + 贝叶斯/多目标优化]→ Top-N 候选配方
             └─[模块C AI性能预测(代理模型, 内嵌打分)]→ 各配方多性能预测值+置信区间
                  └─[模块D LLM+RAG+SHAP: 多方案对比/雷达图/推荐理由/LCC·碳排放]→ 推荐报告
                       └─[模块E 反馈闭环(概念设计, 加分项)]
   全程由 [模块F 前后端原型 + 集成接口] 承载演示
```

## 1. 核心问题是什么

赛题的**核心命题**（PDF 原文）：在养护决策系统中嵌入沥青材料方案智能推荐引擎，让养护决策不止步于"修什么（工法）"，而是进一步回答 **"用什么材料修、为什么用这个材料、预期效果如何"**，打通 **`养护决策 → 材料设计 → 性能预测 → 方案推荐`** 的闭环。

拆成 4 个真正的技术难题（这就是评委的打分点）：

| # | 核心问题 | 本质 | 你们的抓手 |
|---|---------|------|-----------|
| P1 | **场景→性能的量化映射** | 把"气候分区+交通荷载+病害类型/严重度"翻译成"高温PG/低温PG/疲劳寿命/水稳定性/动态模量"的目标值 | 规则库(规范)+数据驱动回归+向量检索/结构表，输出结构化目标指标 |
| P2 | **配方反向设计与智能推荐**（核心环节） | 在给定目标性能+约束下，从上千种组合（基质沥青标号/SBS·橡胶·高粘高弹改性/AC·SMA·OGFC·Superpave级配/抗剥落·抗车辙·温拌·再生助剂）里推最优 | 知识库召回候选 + 多目标贝叶斯优化/案例检索 |
| P3 | **多性能 AI 协同预测 + 小样本** | 一个模型同时预测多项性能，且数据"小样本、高噪声、多源异构" | 多任务学习 + 迁移/元学习 + 机理-数据混合(PINN)，输出带置信区间 |
| P4 | **可解释 + 动态闭环** | 讲清"为什么推荐这个配方"，并能随实测数据进化 | SHAP/LIME + "推荐→验证→反馈→优化"持续学习机制（闭环做概念设计即可） |

**三大行业瓶颈（背景痛点，写说明书立项依据直接用）：**
1. **材料方案滞后于养护决策**——决策系统能出"铣刨重铺上面层/裂缝处治"，但"用什么沥青、什么级配、什么改性方案"仍靠工程师经验，从决策到落地要数天乃至数周。
2. **材料推荐缺乏量化依据**——不同场景对高温抗车辙/低温抗裂/水稳定/疲劳要求差异显著，但缺"场景参数→性能需求"的量化映射，更缺"性能需求→配方"的反向推导。
3. **材料方案与施工工艺脱节**——同一配方在不同拌和温度/摊铺/压实条件下性能差异可达 **30%以上**，缺"材料-工艺"协同优化。

## 2. 背景意义 / 挑战性 / 公开数据集（真实可访问）

### 2.1 背景意义
- 我国公路已进入 **大规模存量养护时代**：2025 年全国公路总里程达 **557.89 万公里**，服役超 12 年的沥青路面占比持续上升，**每年养护工程沥青混合料用量超 3 亿吨**（PDF 原文，引自交通运输部统计）。
- 意义链条：**降本（材料/研发周期）+ 提寿命（性能匹配）+ 降碳（全生命周期碳排放）+ 提效（决策到方案从数周→分钟级）**。这四条正好对应商业计划书的"预期经济效益"。

### 2.2 挑战性（为什么难，写"可行性分析"时要正面回应）
- **小样本、高噪声、多源异构**：材料研发数据天然稀缺，传统深度学习易过拟合。
- **高维组合优化 + 多目标权衡**：配方空间上千维，高温/低温/疲劳/水稳/成本/碳排放目标互相冲突（典型 Pareto 问题）。
- **机理-数据一致性**：纯数据模型可能给出"物理上不合理"的配方，需嵌入材料科学机理（PG分级、四组分、SBS改性机理）。
- **可解释性**：工程师不接受黑箱，必须能追溯"为什么"。
- **跨材料体系泛化**：基质/SBS/橡胶/再生沥青光谱与性能分布差异大，冷启动难。

## 3. 核心方案如何设计 / 我们的核心方法是什么

### 3.1 一句话描述（打磨版）
> **"气候分区 + 交通载荷 + 病害特征 → 量化目标性能 → 反向设计沥青混合料配方 → 多方案对比推荐报告"** 的 AI 选材智能体：以**向量知识库(RAG)+结构化关系表 + 多性能代理模型 + 多目标优化**提供量化依据，以 **LLM+RAG** 做编排、可解释与报告生成。

### 3.2 核心方法（技术路线，分 6 模块）

**模块 A：养护场景 → 目标性能需求映射模型**
- 输入：气候分区（高温/低温 PG 分区）、交通荷载等级（ESALs/轴次）、路面结构形式、病害类型与严重度、约束（预算/工期/环保）。
- 方法：**规范规则库（查表基线）+ 数据驱动回归（LTPP 训练）+ 向量检索/结构表推理** 三者融合；输出目标性能指标（高温PG、低温PG、动稳定度/flow number、疲劳寿命、水稳定 TSR、E\* 等）。
- **性能需求优先级排序机制**：多约束下用 AHP/熵权或学习到的权重，对高温/低温/疲劳/水稳/施工和易性做**权重分配与优先级排序**（这是赛题明确点名要的）。
- 输出：结构化 JSON（场景标签 + 目标性能向量 + 权重），作为模块 B 输入。

**模块 B：沥青混合料智能推荐引擎（核心环节）**
- **技术选型定调：不用 Neo4j，改用「向量知识库(RAG) + 轻量结构化关系层(SQLite/CSV)」**（赛题"成果(2)"明确允许"知识图谱、规则库、数据库、向量知识库等形式，不限定技术路线"）。
  - **向量知识库（主力）**：把规范条文、工程案例、材料说明、企业资料切块入库(Chroma/FAISS)，用**混合检索（向量语义 + BM25 关键词）+ rerank(bge-reranker)**；负责场景解析、案例召回、推荐理由生成、可解释问答。
  - **结构化关系层（轻量，1天可建）**：用 SQLite 存"**材料组成—性能表现—适用场景**"三元关系表 + 配方-性能矩阵。实体：沥青品种（基质标号/SBS/橡胶/高粘高弹）、级配类型（AC/SMA/OGFC/Superpave）、功能助剂（抗剥落/抗车辙/温拌/再生剂）；关系：改性剂掺量→PG提升、级配→抗车辙/抗滑、助剂→水稳等。**这层专门提供定量依据，供候选召回与优化打分**（纯语义 RAG 给不出定量关系，必须靠它守住"量化依据"红线）。
- **"目标性能→配方"推荐算法**：
  - 第一层**候选召回**：结构化关系层 SQL 过滤 + 向量 RAG 案例检索（相似历史场景的成功配方）缩小搜索空间；
  - 第二层**多目标优化**：以模块 C 的预测模型为代理，用 **多目标贝叶斯优化（如 qNEHVI / BoTorch）或遗传/粒子群(PSO)** 在配方空间求 Pareto 前沿，兼顾性能达标 + 成本 + 碳排放；
  - 输出 Top-N 候选配方（沥青品种 + 改性剂类型/掺量 + 级配范围 + 助剂方案）。
- **作用**：这是把"经验选型"变成"量化反向设计"的核心创新点。

**模块 C：多性能 AI 协同预测模型（代理模型）**
- 输入：材料组成参数（沥青品种、改性剂类型/掺量、级配、油石比、空隙率）+ 环境因素（温度、荷载频率、老化条件）。
- 同时预测：高温抗车辙、低温抗裂、疲劳寿命、水稳定性、动态模量 E\*（**多任务学习**，共享底座 + 多输出头）。
- **小样本策略**（赛题点名）：迁移学习（大数据预训练→目标体系微调）、元学习(Few-shot)、数据增强(GAN 合成)、**机理-数据混合(PINN)**——把 PG 分级/黏弹性机理作为物理约束嵌入损失。
- 输出：各性能预测值 + **置信区间**（用 MC-Dropout / 深度核 / 分位数回归）。
- **作用**：既是模块 B 优化器的"打分器"，也是最终方案的"验证器"。

**模块 D：多方案对比 + 可解释推荐理由（LLM+RAG）**
- **可解释 AI**：对模块 C 用 **SHAP/LIME** 揭示"哪个材料参数对哪项性能贡献最大"，回答"为什么推荐这个配方"。
- **多维对比可视化**：关键性能、**全生命周期成本(LCC)、碳排放、预期寿命、施工可行性** 的**雷达图**并列对比。
- **LLM+RAG 报告生成**：把量化结果 + 知识库证据 + SHAP 解释组织成自然语言推荐理由与对比分析，**所有结论可溯源到知识库/数据/规范**（避免幻觉）。

**模块 E：反馈闭环（概念设计，加分项）**
- 推荐方案实施后，路用性能监测数据回流，增量/在线学习更新模块 B/C，形成"推荐→验证→反馈→优化"持续学习机制。MVP 阶段做**架构图 + 数据回流接口设计**即可，不要求真跑。

**模块 F：集成与交互（前后端）**
- 定义**接口规范**：养护决策系统输出（病害类型/严重度/目标性能/预算）↔ 推荐引擎输出（配方/性能预测/成本）的标准数据格式与交互协议（JSON Schema + REST API）。
- **模块化松耦合架构**：各模块独立 API，便于对接不同来源决策系统与材料库。
- **智能交互界面**："输入养护场景→自动生成材料方案→查看预测性能→多方案对比→人工微调确认"全流程。

### 3.3 子任务拆解（输入 / 输出 / 作用）

| 子任务 | 输入 | 输出 | 起到的作用 |
|--------|------|------|-----------|
| **T1 场景解析与标签化** | 自然语言/结构化养护场景 | 标准化场景标签(气候/荷载/病害/约束) | 统一入口，支撑检索与案例匹配 |
| **T2 场景→性能映射(A)** | 场景标签 | 目标性能向量 + 优先级权重 | 把"修什么"翻译成"要什么性能"，量化依据起点 |
| **T3 材料知识库(向量库+结构表)** | 规范/文献/企业资料/案例 | 向量索引(Chroma/FAISS) + SQLite 三元关系表 | 可检索、可推理、可定量匹配的材料知识底座 |
| **T4 多性能预测模型(C)** | 配方+环境参数 | 多性能预测值+置信区间 | 优化打分器 + 方案验证器（小样本+可解释） |
| **T5 反向设计推荐引擎(B)** | 目标性能+约束+图谱+T4 | Top-N 候选配方 | **核心创新**：性能→配方的多目标优化 |
| **T6 对比与推荐报告(D)** | Top-N配方+预测+SHAP+图谱证据 | 雷达图对比+推荐理由+LCC/碳排放 | 辅助工程师比选，可解释、可溯源 |
| **T7 原型系统与接口(F)** | 上述模块 API | Streamlit/FastAPI 可演示原型 | 承载"输入→推荐→预测→对比→微调"演示 |
| **T8 反馈闭环(E, 加分)** | 实施后监测数据 | 增量学习更新机制(架构) | 体现"持续进化"，加分项 |
| **T9 ≥5 典型案例验证** | 场景+约束 | 候选方案+理由+性能预期+基准对比 | 满足赛题"不少于5个典型场景推荐验证"硬性成果 |

**最终合成一个总项目方案**：T1→T2→(T3+T4)→T5→T6，由 T7 承载，T8 收口闭环，T9 完成成果验证与效益测算。

## 4. 当前领域对比方法（真实文献，一次性列全）

### 4.1 机理/经验基线（必须对比的传统方法）
- **Witczak / 修正 Witczak / Bari-Witczak / Hirsch / Al-Khateeb 动态模量 E\* 预测模型**——经典机理-经验模型，作为 E\* 预测的基线。综述见 ASU 博士论文：http://m.zhangqiaokeyan.com/academic-degree-foreign_mphd_thesis/02061201750.html
- **规范查表法**（Superpave PG 分级 + JTG 养护/施工规范）——传统经验选型基线。

### 4.2 机器学习性能预测（同类 SOTA）
- **ANN / GP / GMDH 数据驱动 E\* 估计**（1320 数据点，训练/测试 R²≈0.982/0.984，优于 Witczak 等全部经验模型）：https://m.zhangqiaokeyan.com/journal-foreign-detail/0704036467688.html
- **XGBoost-SHAP 路面状况评估框架**：Gupta et al., 2024, *Construction and Building Materials*, 426, 136182（可解释 ML 标杆）。
- **集成 GBDT 路面性能预测**：Guo, Fu, Sollazzo, 2022, *Int. J. Pavement Engineering*, 23(10):3633-3646。

## 5. 前后端 + 演示视频

### 5.1 技术选型（**面向 11 天可交付、且不假设本地有强算力/大数据**）
- **首选轻量方案（强烈推荐）**：后端 **FastAPI**（模块即服务）＋ 前端 **Streamlit**（1 天出可用界面，支持表单输入、雷达图、对比表）。可视化用 **ECharts / Plotly**（雷达图、Pareto 前沿、SHAP 瀑布图）。
- **知识库/RAG（定调：不用 Neo4j）**：向量库用 **Chroma 或 FAISS**（本地轻量）；结构化"材料-性能-场景"关系用 **SQLite（或 CSV/JSON）关系表**；检索用 **混合检索(向量+BM25)+rerank(bge-reranker)**；中文 embedding 用 **bge-m3 / bge-large-zh**（CPU 可跑）或走 API；LLM 走 **API 调用**（用团队已有可用的大模型 API，不自建）。
- **模型**：模块 C 用 **LightGBM/XGBoost 多任务 或 PyTorch 小型多输出网络**（CPU 可训），PINN 作为**加分项**（有时间再上）。
- **数据**：LTPP 抽取子集 + 构造配方-性能矩阵（标注为模拟/构造），全部 CSV 化，Git 管理。

> 备选（若团队前端强、时间够）：React + ECharts 前端 + FastAPI 后端，观感更像"产品"，但**开发成本高、11 天风险大**，非首选。

### 5.2 演示流程（原型必须能跑通这条线）
1. 选择/输入养护场景（例：华南高温重载区、沥青路面车辙严重、重交通）；
2. 系统输出目标性能指标 + 优先级权重（模块 A）；
3. 一键生成 Top-3~5 候选材料配方（模块 B）；
4. 展示各配方多性能预测值 + 置信区间 + 雷达图对比 + LCC/碳排放（模块 C+D）；
5. 给出可解释推荐理由（SHAP + 图谱证据溯源）；
6. 工程师人工微调某参数→实时刷新推荐（体现"人在回路"）；
7. 切换展示 **≥5 个典型案例**（高温重载车辙处治 / 寒冷地区裂缝处治 / 水损害路段修复 等）。

## 8. 产品化 / 服务化包装（商业计划书用）

**产品定位**：面向道路养护行业的 **"AI 数智选材 SaaS 平台"**——把养护决策系统与沥青材料方案设计打通的推荐引擎。

**产品/服务形态**：
1. **SaaS 平台（订阅制）**：公路局/养护公司/设计院登录即用，输入场景→出材料方案报告。按坐席或按项目订阅。
2. **API/PaaS（按次或包量计费）**：以标准接口嵌入既有**养护决策系统/资产管理系统**，做"材料智能"插件（对应赛题模块F的接口规范）。
3. **定制解决方案（项目制）**：为特定区域/材料体系做数据对接、模型微调、知识库定制。
4. **数据资产服务**：沉淀"场景—材料—性能"结构化知识库，形成可复用数据资产，反哺模型持续进化（模块E）。

**目标客户**：交通运输主管部门/公路事业发展中心、公路养护企业、道路材料供应商（**海韵这类产业链服务商是天然首批客户/渠道**）、设计咨询院。

**竞争优势**：
- **闭环独特性**：市面养护决策系统止步"修什么"，我们回答"用什么材料修、为什么、预期效果"——填补"决策↔材料设计"技术鸿沟。
- **量化+可解释**：向量知识库(RAG)+结构化关系表+预测模型+优化器提供量化依据，SHAP 提供可解释，规避纯 LLM 幻觉。
- **多目标**：性能、LCC、碳排放一体权衡，契合"双碳"与全生命周期管理趋势。

**商业模式**：订阅费 + API 调用费 + 定制开发费 + 数据服务费；与揭榜企业共建"产学研用"孵化（赛题承诺：优秀方案可对接企业研发项目、导师团队、优势高校课题组，提供经费与算力/实验室验证）。

**预期经济效益（写测算要标假设与数据来源）**：
- 材料方案设计周期从**数天/数周 → 分钟级**；
- 材料成本下降（精准匹配避免过度设计）；
- 预期寿命提升（性能与场景匹配）；
- 碳排放下降（配合 RAP 再生、温拌助剂优化）；
- 研发试配次数减少（优化器替代大量室内试验）。

**发展路线（Roadmap）**：MVP(本次比赛原型) → 企业脱敏数据接入与模型微调 → 试点工程验证(实验室+现场) → 与养护决策系统正式联调 → 区域级 SaaS 上线 → 全国推广 + 持续学习闭环。
