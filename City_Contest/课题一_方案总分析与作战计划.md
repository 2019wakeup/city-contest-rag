## 0. 一句话新定位

原 v1 的六模块大方案已由全队分工承接；**本项目（本仓库）聚焦交付可演示的「LLM + RAG + 向量知识库 + 前后端」系统**，即模块 **B（召回）+ D（LLM+RAG 报告）+ F（前后端原型）**；模块 A（场景→性能映射）与 C（性能预测模型）由队友实现，双方通过 **JSON 契约 + mock** 并行开发、最后对接。

核心原则不变：**量化依据全确定性计算，LLM 只负责文案与解释**；检索稳定性的四道防线（接口抽象 / 语料即真相源 / provenance / 金标准回归集）见 spec §4。

## 2. 技术栈（一图）

```
Vue3+Vite+Element Plus+ECharts 前端  ──REST──▶  Hono 后端（Node 24, TypeScript）
                                                  ├─ adapters：模块A/C 客户端（mock ⇄ 队友真实服务）
                                                  ├─ 检索：LanceDB 混合检索（降级 SQLite FTS5+vec）
                                                  ├─ 关系表：better-sqlite3
                                                  ├─ embedding：transformers.js 本地 bge-m3（中英均衡）
                                                  └─ LLM：DeepSeek API（openai SDK，.env 配置）
```

明确**不引入** agent 框架（Mastra/LangGraph 赛后再说）与重型向量库服务器（Milvus 需要 server，Lite 仅 Python）——调研依据见 spec §13。

## 5. 与 v1 的差异摘要（为什么这样改）

1. **范围收窄**：从"六模块全做"收窄为 B+D+F 三个可闭环演示的模块，A/C 外包给队友走契约——11 天里这是唯一能跑通、能演示的切法。
2. **LLM 定位**：v1 已定"LLM 只编排不拍配方"，v2 进一步落地为"数值全确定性、LLM 只写文案、prompt 禁止编造证据"。
3. **向量库策略升级**：v1 说"Chroma/FAISS"，v2 改为"LanceDB 默认 + SQLite 降级 + 四道防线"，直接回应"向量库不稳定"的风险。
4. **数据红利**：v1 只有题录，v2 已有 81/149 全文 + 8 份规范原文 + MinerU 提取管线，语料质量显著升级。
